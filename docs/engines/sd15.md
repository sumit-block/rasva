# Stable Diffusion 1.5 (phase I0 baseline: image generation)

Status: installed and generating on the target M2. It was started before the
audio release gate by owner decision ([ADR-0006](../adr/0006-image-baseline-early.md)).
Description in, one 512 × 512 PNG out. This is a baseline, not the final image quality.

## Measurements on the M2 (2026-11-20)

The Mac is an M2 with 16 GB of memory. The runs used diffusers 0.43.0 and
torch 2.11.0 on the Apple GPU (MPS) in fp16, with the model files pinned at
`451f4fe`, the DPM++ 2M scheduler, 25 steps (Balanced) and guidance 7.5. They
went through the API: 5 descriptions plus a repeat of the first with the same
seed.

| Measure | Result | How it was measured |
| --- | --- | --- |
| Runs | 6 completed, 0 failed | Plus 3 + 2 runs in a scratch environment against the same installed files |
| Model load (cold) | 14.5 s in the app (4.5–5.2 s in the scratch runs, with files already in the OS cache) | Starting the worker and loading the pipeline to the GPU |
| Time per image | median 52.6 s (range 43.0 to 54.4 s), about 2.1 s per step | The first image after load is the fastest. On CPU (float32) the same work took 94–104 s, so the GPU is the default |
| Memory | worker RSS 0.47 GB; GPU memory reserved by the driver 8.5 GB (8,500,412,416 bytes) | `torch.mps.driver_allocated_memory()` sampled every step. It includes PyTorch's cached pool, so it is an upper bound on what the model needs. RSS does not count GPU memory. On CPU the process peaked at 6.46 GB RSS |
| Installed size | 2.75 GB (2,751,901,696 bytes) | Disk blocks measured by the installer: model files 2.13 GB, plus the Python 3.12 environment |
| Reproducible | yes | The same description and seed gave a byte-identical PNG (the noise comes from a CPU generator) |
| Unloads; no effect on audio | yes | After the image jobs, a Kokoro narration started cold and completed. Only Kokoro's worker was left running |
| Network use | none | A load-and-generate run with every socket blocked made 0 attempts, and no new files appeared in the home folder |
| Privacy | prompts stay out of logs | Grepped the engine and app logs after the runs, including a 136-token prompt that was truncated |

## Decisions

| Decision | Why |
| --- | --- |
| diffusers on PyTorch, own Python 3.12 environment | This is the same pattern as the audio engines, and I1–I3 adapters build on diffusers (ADR-0006) |
| fp16 safetensors only, from an explicit file list | 2.13 GB instead of 4+ GB. No `.ckpt` (pickle) files, no EMA weights |
| No safety checker | Owner decision (ADR-0006). It is not downloaded, and the pipeline runs with `safety_checker=None`. The Models page and Image Studio say images are not screened |
| Apple GPU (MPS) in fp16 by default; CPU in float32 | The GPU was about twice as fast on the M2. `RASVA_TORCH_DEVICE=cpu` overrides it. If loading on MPS fails, the engine logs why and reloads on CPU |
| **No attention slicing** | With fp16 on MPS, slicing turned every latent into NaN on the M2, so all images came out blank. PyTorch's built-in attention is already memory-efficient |
| Refuse blank or NaN images | An all-black or NaN result is an error with a plain message, never a saved file |
| Seed chosen when the job is created | It is stored in the job's inputs, so Retry and "same seed" reproduce the image. The noise comes from a CPU generator, so a seed gives the same start on any device |
| DPM++ 2M scheduler | Good results in 20–30 steps. The default PNDM scheduler wants about 50 |
| Presets Quick / Balanced / Detailed = 15 / 25 / 40 steps | Plain choices. Advanced mode adds Avoid (negative prompt), seed, steps and guidance |
| Long prompts | CLIP reads 77 tokens. Longer prompts are cut, and the job's `truncated_prompt` metric says so. Library warnings that would quote the cut text are silenced |

## Not done yet (I0 and later)

- An image review by eye of quality and failure cases. The PRD's I0 gate also
  asks for quality notes.
- Image experiments with the PRD §20.2 weights: the experiment service is
  still narration-only.
- Higher resolutions, image-to-image, reference photos and poses: these are
  I1–I3.
- Whether 8.5 GB of GPU memory leaves enough headroom when other apps are
  open. The memory guard (README, "Memory guard") now holds a cold start until
  psutil reports 10 GB available (the 9 GB peak in the descriptor plus the
  1 GB default margin). The 8.5 GB is an upper bound that includes PyTorch's
  cache, and psutil's `available` leaves out compressible memory, so the guard
  may make image jobs wait when they would have fitted. Not yet checked on the
  M2 with the real engine; lowering the margin in Settings → Memory is the
  owner's lever if it proves too strict.
